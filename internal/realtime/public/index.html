A simple, high-performance real-time database layer on top of SQLite. All REST API endpoints are prefixed with /db.

System Health

GET /health

Checks the health of the server and its database connection.

curl http://localhost:17050/health

Success Response (200 OK):

{ "status": "ok", "database": "connected" }

Collections & Schema

GET /db/collections

Lists all user-created collections and their schema definitions.

curl http://localhost:17050/db/collections

Success Response:

[
  {
    "name": "orders",
    "schema": [
      { "name": "total", "type": "int" },
      { "name": "status", "type": "text" }
    ]
  },
  {
    "name": "users",
    "schema": []
  }
]

GET /db/collections/{collectionName}

Retrieves the schema definition for a specific collection.

curl http://localhost:17050/db/collections/orders

Success Response:

{
  "name": "orders",
  "schema": [
    { "name": "total", "type": "int" },
    { "name": "status", "type": "text" }
  ]
}

POST /db/collections

Creates a new collection with an optional typed schema. Fields defined here become native SQL columns for performance. Other fields go into the JSON blob.

Supported Types: text, int, float, bool, datetime.

curl -X POST http://localhost:17050/db/collections \
  -H "Content-Type: application/json" \
  -d '{
    "name": "orders",
    "schema": [
        { "name": "status", "type": "text", "required": true },
        { "name": "total", "type": "int" },
        { "name": "created_at", "type": "datetime" }
    ]
  }'

Success Response:

{ "status": "created", "collection": "orders" }

PATCH /db/collections/{collectionName}

Schema Migration. Allows promoting fields (JSON -> Column), demoting fields (Column -> JSON), adding new columns, or deleting columns.

Example: Promote 'region' to a column (Extracts existing data)
curl -X PATCH http://localhost:17050/db/collections/orders \
  -H "Content-Type: application/json" \
  -d '{
    "promote": [
      { "name": "region", "type": "text" }
    ]
  }'
Example: Add a new empty column
curl -X PATCH http://localhost:17050/db/collections/orders \
  -H "Content-Type: application/json" \
  -d '{
    "add": [
      { "name": "priority", "type": "int" }
    ]
  }'
Example: Demote 'total' back to JSON blob
curl -X PATCH http://localhost:17050/db/collections/orders \
  -H "Content-Type: application/json" \
  -d '{
    "demote": ["total"]
  }'
Example: Delete 'legacy_field' column permanently
curl -X PATCH http://localhost:17050/db/collections/orders \
  -H "Content-Type: application/json" \
  -d '{
    "delete": ["legacy_field"]
  }'

Success Response:

{
  "status": "updated",
  "collection": "orders",
  "schema": [...] // New schema
}

DELETE /db/collections/{collectionName}

Deletes a collection and all its data permanently.

curl -X DELETE http://localhost:17050/db/collections/orders

Success Response:

{ "status": "deleted" }

Indexes

POST /db/indexes/{collectionName}

Creates an index. If the field is in the schema, it uses a native SQL index. If not, it creates a JSON expression index.

curl -X POST http://localhost:17050/db/indexes/orders \
  -H "Content-Type: application/json" \
  -d '{
    "name": "idx_total",
    "fields": ["total"],
    "unique": false
  }'

Success Response:

{ "status": "created", "index": { ... } }

Documents (CRUD)

PUT /db/data/{collection}/{docId}

Upsert. Creates a new document or fully replaces an existing one. Any field not included in the payload will be lost.

curl -X PUT http://localhost:17050/db/data/orders/ord_100 \
  -H "Content-Type: application/json" \
  -d '{
    "status": "pending",
    "total": 150,
    "region": "US",
    "notes": "urgent delivery"
  }'

Success Response:

{ "status": "replaced", "id": "ord_100", "operation": "INSERT" }

PATCH /db/data/{collection}/{docId}

Partial Update. Merges new fields into the existing document (RFC 7396 Merge Patch).

curl -X PATCH http://localhost:17050/db/data/orders/ord_100 \
  -H "Content-Type: application/json" \
  -d '{
    "status": "shipped", 
    "shippedAt": "2025-10-01T12:00:00Z"
  }'

Success Response:

{ "status": "patched", "id": "ord_100" }

GET /db/data/{collection}/{docId}

Retrieves a single document. Reconstructs the full JSON from columns + blob.

curl http://localhost:17050/db/data/orders/ord_100

Success Response:

{
  "id": "ord_100",
  "status": "shipped",
  "total": 150,
  "region": "US",
  "notes": "urgent delivery",
  "shippedAt": "2025-10-01T12:00:00Z"
}

DELETE /db/data/{collection}/{docId}

Deletes a document.

curl -X DELETE http://localhost:17050/db/data/orders/ord_100

Success Response:

{ "status": "deleted", "id": "ord_100" }

POST /db/batch

Bulk Operations. Execute multiple PUT, PATCH, or DELETE operations in a single atomic transaction. Highly recommended for bulk imports.

curl -X POST http://localhost:17050/db/batch \
  -H "Content-Type: application/json" \
  -d '{
    "operations": [
      { "method": "PUT", "collection": "orders", "docId": "ord_1", "data": {"total": 100} },
      { "method": "PATCH", "collection": "orders", "docId": "ord_2", "data": {"status": "done"} },
      { "method": "DELETE", "collection": "orders", "docId": "ord_3" }
    ]
  }'

Success Response:

{ "status": "success", "count": 3 }

Querying

POST /db/query/{collectionName}

Executes a read-only query. Returns an array of document wrappers { id, data }.

Example: Find VIP Orders

Find orders where Region is 'EU' AND Total > 100, sorted by Total.

curl -X POST http://localhost:17050/db/query/orders \
  -H "Content-Type: application/json" \
  -d '{
    "where": {
      "$and": [
        { "field": "region", "op": "==", "value": "EU" },
        { "field": "total", "op": ">", "value": 100 }
      ]
    },
    "orderBy": [
      { "field": "total", "direction": "desc" }
    ],
    "limit": 20
  }'

Example Response:

[
  {
    "id": "ord_200",
    "data": { "status": "pending", "total": 500, "region": "EU" }
  },
  {
    "id": "ord_350",
    "data": { "status": "shipped", "total": 120, "region": "EU" }
  }
]

WebSocket API

Connect to ws://localhost:17050/ws to receive live updates.

Protocol Details (JSON Stream)

To maximize performance, the server utilizes a JSON Stream protocol.

Important: A single WebSocket message frame may contain multiple JSON objects separated by the ASCII Record Separator (\x1e) character.
Clients must split the frame data by this delimiter (not newline) to parse individual JSON objects safely, preventing issues if the JSON data itself contains newlines. 
// Raw Frame Content Example (Using RS delimiter)
{"type": "realtime_update", ...}\x1e{"type": "realtime_update", ...}

Message Format

Send: {"type": "subscribe", "subscription": {...}}

Subscribe with Query (Live Dashboard)

{
  "type": "subscribe",
  "subscription": {
    "subscriptionId": "sub-3",
    "collection": "orders",
    "query": {
      "where": {
        "field": "status",
        "op": "==",
        "value": "pending"
      }
    }
  }
}

Server Events

The server sends the following JSON payloads over the socket.

1. Acknowledgment

Sent immediately after subscribing. Provides the internal Topic ID used for routing.

{
  "type": "subscribe_ack",
  "subscriptionId": "sub-3",
  "topic": "query:orders:4139481239"
}
2. Initial Data Batch

A chunk of existing data matching your query. Sent sequentially.

{
  "type": "initial_data_batch",
  "subscriptionId": "sub-3",
  "collection": "orders",
  "documents": [
    { "id": "ord_1", "data": { ... } },
    { "id": "ord_2", "data": { ... } }
  ]
}
3. Initial Data Complete

Signals that all existing data has been sent. Live updates begin after this.

{
  "type": "initial_data_complete",
  "subscriptionId": "sub-3",
  "collection": "orders"
}
4. Real-Time Update

A live change event. Grouped by topic for efficiency.

{
  "type": "realtime_update",
  "topic": "query:orders:4139481239",
  "payload": {
    "operation": "INSERT", // INSERT, UPDATE, DELETE, REMOVE
    "collection": "orders",
    "docId": "ord_999",
    "data": { "status": "pending", "total": 50 }
  }
}
